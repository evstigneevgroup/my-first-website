# Таблица учёта треков

Рабочая таблица библиотеки. Без неё через полгода вы не найдёте ни один свой трек и начнёте заново (урок 1.6).

---

## Правило одного касания

**Трек отмечается сразу после первого прослушивания.** Не «когда пойдёт в плейлист», не «когда понравится больше» — сразу.

Логика простая. Трек, который вы не отметили, через неделю вы не вспомните. Через месяц вы не найдёте его в папке. Через три месяца вы скажете «у меня ничего своего нет», и это будет правдой — не потому что треков не было, а потому что они остались в папке с именами вида `unknown_04.mp3`. Плейлист, который ведётся по правилу одного касания, растёт на 30–50 позиций в месяц сам собой.

**Что значит «сразу»:** дослушали трек до конца или дошли до 1:30, записали — и закрыли файл. Пока трек не дослушан, он не ваш.

## Колонки

```
№   ТРЕК                     АРТИСТ           ПУТЬ К ФАЙЛУ              ДАТА   СТИЛЬ    BPM  CAMELOT  ЭН.  HOT CUE  ОТМЕТКА
1   ______________________   ______________   _____________________   ____   ______   ___   8A      ___   HC1 ___   __________
```

| Колонка | Что писать | Зачем нужна |
|---|---|---|
| № | Порядковый номер добавления | Считать объём библиотеки и видеть темп роста |
| Трек | Название так, как в софте | Поиск и сверка |
| Артист | Тот же порядок, что в названии | Фильтр по исполнителю |
| Путь к файлу | Относительный путь от папки музыки | При переезде библиотеки путь чинится за 10 минут |
| Дата | Дата первого прослушивания в формате `ГГГГ-ММ-ДД` | Отдельно от даты добавления: трек мог лежать месяц |
| Стиль | Одно слово: house, hip-hop, rnb, dnb, pop, afrobeats | Фильтр при выборе жанра под площадку |
| BPM | Целое число | Скорость |
| Camelot | Две буквы и цифра, например `9A` | Совместимость переходов |
| Эн. | Цифра 1–10 | Место в лестнице |
| Hot cue | Что стоит на метке: дроп, брейк, вокал, снятие баса | Помогает не переслушивать трек перед сетом |
| Отметка | `+` рабочий, `?` под вопросом, `−` не брать | Быстрый отсев |

**Символы в колонке «отметка»:**

- `+` — играл на выступлении, оставляю в библиотеке навсегда
- `−` — не беру ни при каких условиях, удаляю через месяц, если не пожалел
- `?` — не понял, послушать ещё через 2 недели

## Правила ведения

1. **Одна строка — один трек.** Версии, ремиксы и редакции — отдельные строки: у них разные BPM и разные Camelot.
2. **Дата — это дата первого касания.** Исправлять её задним числом не нужно: несовпадение с датой в файлах — нормально и даже полезно, так видно, что вы систематически откладывали.
3. **Переезд библиотеки не трогает таблицу.** Меняется только колонка с путём; ищите и заменяйте старую папку на новую поиском по названию.
4. **Треки без анализа не попадают в таблицу.** Нет BPM и Camelot — это не ваша музыка, это файлы. Разбираются они отдельной задачей: 20 треков за вечер.
5. **Один вечер — одна правка.** Закончили сет, на следующий день вписали, что сыграли. Не копите две недели: через две недели вы вспомните три трека из сорока.
6. **Символ `−` не удаляет файл с диска сразу.** Файл удаляется через месяц. Если за этот месяц вы его пожалели — символ меняется на `+`, файл остаётся.

## Еженедельная рубрика

Раз в неделю, в один и тот же день, 20 минут. Без этого правила таблица разрастается до 3 000 строк и перестаёт быть рабочей.

```
НЕДЕЛЯ: ____  (число недели / дата)

ДОБАВЛЕНО ЗА НЕДЕЛЮ: ____ треков
ИЗ НИХ ОТМЕЧЕНО +: ____ треков
ИЗ НИХ ОТМЕЧЕНО −: ____ треков
ВСЕГО В ТАБЛИЦЕ: ____ треков
ВСЕГО С МЕТКОЙ +: ____ треков

ПРОВЕРКИ:
[ ] Каждый новый трек имеет BPM и Camelot (не пусто ни в одной новой строке)
[ ] Ни один трек не остался с отметкой `?` дольше двух недель
[ ] Файлы с отметкой `−` удалены или перенесены в папку `не_используется`
[ ] Хотя бы один трек из таблицы реально прозвучал за неделю
[ ] Папка с музыкой и носитель содержат одинаковый набор (проверено по числу файлов)
[ ] Библиотека с анализирована (нет значка ожидания)

ДЫРЫ ПО КОЛЕСУ (Camelot, где треков меньше трёх):
8A ___   9A ___   10A ___   11A ___   11B ___   12B ___   1B ___   8B ___

ЗАДАЧА НА СЛЕДУЮЩУЮ НЕДЕЛЮ: найти по 3 трека в позиции ____________ и ____________

ТРИМЕНТА НЕДЕЛИ (что я узнал про свою музыку):
1. ______________________________________________________________________
2. ______________________________________________________________________
3. ______________________________________________________________________
```

## Итоги по месяцу

Раз в четыре недели, 30 минут. Четыре цифры, которые показывают, растёте вы или стоите на месте:

```
МЕСЯЦ: ____________

ВЫСТУПЛЕНИЙ: ____
ТРЕКОВ ДОБАВЛЕНО: ____
ТРЕКОВ С МЕТКОЙ + ПОЯВИЛОСЬ: ____
СРЕДНЯЯ ЭНЕРГИЯ СЕТА: ____ / 10
САМЫЙ ЧАСТЫЙ СТИЛЬ: ____________
СТИЛЬ, КОТОРЫЙ НИ РАЗУ НЕ ЗАХОДИЛ: ____________
ПРОБЛЕМА, КОТОРАЯ ПОВТОРЯЕТСЯ: ____________________
```

**Что считать признаком роста.** Не количество треков в библиотеке и не число выступлений. Признак роста — средняя энергия сета и доля переходов, которые вы делаете без ручной подстройки джогом. Если энергия сета за полгода поднялась с 5 до 7, а переходы стали ровными по сетке, вы выросли. Если энергия упала с 7 до 5, потому что вы играете «для своих», — вы не выросли, вы сузили площадку.

## Хранение

```
Мои_сеты/учёт/треки.csv          ← основная таблица, одна на всю библиотеку
Мои_сеты/учёт/треки_2026-05.csv  ← месячная копия, не трогаем
Мои_сеты/учёт/недели.md         ← еженедельные рубрики, по одной записи в неделю
Облако/учёт/                     ← синхронизация, 0 ₽
```

Три файла, одна папка. Таблицу удобнее вести в текстовом файле с разделителем табуляцией или в таблице: фильтр по стилю и по Camelot работает без макросов, а главное — файл открывается на любом компьютере, включая тот, где нет вашего софта.
